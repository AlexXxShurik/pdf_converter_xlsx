# AGENTS.md — план реализации: извлечение данных из PDF-каталога в XLSX

## Исходные данные (фактические файлы в корне)

| Файл                             | Описание                                              |
|----------------------------------|-------------------------------------------------------|
| `Каталог Deskar_compressed.pdf`  | Входной каталог, 252 стр., формат A4, БЕЗ текстового слоя (страницы — растровые изображения, подтверждено: `page.get_text() == ""`, 1 картинка на страницу). Ссылаться в коде как `input.pdf` через константу/аргумент. |
| `образец.xlsx`                   | Эталон структуры результата (см. ниже).               |

Проверено по `образец.xlsx` (внутренности):

- Шапка строго: `model | L | I.C | S | d | r | P | M | K` (колонки A–I).
- Значения размерных атрибутов — числа (`12.9`, `12.7`, `4.76`, `5.16`, `0.4`),
  в XLSX сохранены как numeric, не строки.
- Сплавы пишутся в колонку своей группы P/M/K, причём **группа берётся из
  секции каталога, а не из префикса сплава**: в образце `LF6008`, `LF6018`,
  `LF6118` лежат в колонке `M` (column H).
- Одна модель + несколько сплавов = несколько строк:
  `CNMG120404-HS` дважды (LF6008 и LF6018), атрибуты дублируются.
- В образце есть служебная строка-заметка `ЕСЛИ ЕСТЬ НЕСКОЛЬКО СПЛАВОВ`
  (только в колонке model) — такие шумовые строки нужно отфильтровывать.

## Цель

Из растрового PDF-каталога извлечь: модели, значения размерных атрибутов и сплавы
(группы P/M/K). Результат — `result.xlsx` со структурой:

```
model | L | I.C | S | d | r | P | M | K
```

Правила:

- одна строка = одна комбинация «модель + сплав» (несколько сплавов у модели
  разворачиваются в отдельные строки с дублированием модели и атрибутов);
- без дублей одинаковой комбинации «модель + сплав»;
- числовые атрибуты пишутся в XLSX как числа (не строки);
- написание моделей и сплавов сохраняется максимально как в каталоге;
- на разных страницах набор атрибутов может отличаться — заголовки таблицы
  определяются динамически, а не зашиты жёстко.

## Стек

| Задача             | Инструмент                                            |
|--------------------|-------------------------------------------------------|
| PDF → изображения  | PyMuPDF (fitz)                                        |
| Предобработка      | OpenCV (grayscale, denoise, threshold, morphology)    |
| OCR                | PaddleOCR (координаты блоков + текст)                 |
| Структура таблицы  | Собственная геометрия по OCR-boxes                    |
| Парсинг/валидация  | Python (regex, правила, dedup)                        |
| XLSX               | openpyxl                                              |
| ИИ                 | не используется (детерминированный pipeline)          |

Зависимости: `pymupdf`, `opencv-python`, `paddleocr`/`paddlepaddle`,
`openpyxl`.

## Этапы pipeline

### 1. PDF → PNG страниц
- PyMuPDF рендерит каждую страницу в изображение.
- Масштаб подбирается так, чтобы мелкий текст таблиц стал читаем для OCR
  (увеличение по умолчанию, эмпирическая настройка zoom).

### 2. Предобработка изображения (OpenCV)
- Grayscale + удаление шума (bilateral/median).
- Binarization: adaptive threshold (для неоднородной заливки таблиц).
- Морфологические операции для усиления линий сетки таблицы.
- Каждая страница обрабатывается независимо.

### 3. OCR (PaddleOCR)
- Возвращает список `(text, bbox)` для всех текстовых блоков страницы.
- Используются именно координаты, а не только текст — по ним строится геометрия
  таблицы.

### 4. Построение геометрии таблицы
- Найти область таблицы (скопление блоков в сетке по координатам строк/колонок).
- Кластеризация блоков по Y → строки, по X → колонки.
- Определить строку заголовков (первая строка таблицы с короткими метками вида
  `L`, `I.C`, `S`, `d`, `r`, ...).
- Колонки выравниваются по центроидам X внутри области таблицы.
- Признаки, что это таблица моделей: наличие заголовков + ячейки-значения
  (числа с точкой) + строки-модели.

### 5. Парсинг строк
- Строки таблицы → `Product`:
  - `model` — из первой (или отдельной) колонки, regex-паттерн для моделей
    (буквы+цифры+дефис, напр. `CNMG120404-HS`);
  - `attributes` — значения по динамическим заголовкам колонок, парсятся как
    float;
  - `alloys` — список сплавов, найденных рядом со строкой модели.
- Сплав — токен вида `LF6xxx` (буквы+цифры), ищется:
  - в той же строке таблицы;
  - в блоках-бейджах ниже/рядом, геометрически связанных со строкой модели
    (аналогично примеру `LF6008` / `LF6018` под моделью);
  - группа P/M/K берётся из заголовка секции/колонки, где найден сплав.
- Если набор заголовков на странице другой — атрибуты собираются динамически,
  итоговые колонки XLSX расширяются отсутствующими атрибутами.

### 6. Валидация и нормализация
- Модели/сплавы: нормализация регистра и пробелов, но написание сохраняется.
- Числа: `float()` с безопасным парсингом (запятая/точка, лишние символы).
- Сопоставление «модель + сплав + группа»: проверка, что сплав относится именно
  к этой модели.
- Dedup: `set` ключей `(model, alloy)` — исключение повторных записей, в т.ч.
  пересечений между страницами.
- Отсев шумовых токенов (не модели/не сплавы).

### 7. Генерация XLSX (openpyxl)
- Шапка: `model`, затем найденные атрибуты в порядке появления, затем `P`, `M`,
  `K`.
- Для каждого `(model, alloy)` — одна строка: атрибуты модели + сплав в свою
  колонку группы P/M/K.
- Числа записываются как `float`/`int`, не строки.
- Пустые атрибуты/группы — пустые ячейки.

## Структура кода (предлагаемая)

```
pdf_converter_xlsx/
├── main.py                 # CLI: входной PDF → result.xlsx
├── pdf_to_images.py        # этап 1
├── preprocess.py           # этап 2 (OpenCV)
├── ocr_engine.py           # этап 3 (PaddleOCR, интерфейс с fallback)
├── table_geometry.py       # этап 4 (строки/колонки/заголовки)

├── validator.py            # этап 6 (числа, dedup, нормализация)
├── xlsx_writer.py          # этап 7 (openpyxl)
└── requirements.txt
```

## Порядок работы над задачей

1. Рендер страницы-примера из `Каталог Deskar_compressed.pdf` → посмотреть
   структуру таблицы вживую.
2. Настроить OCR на 1–2 страницах, проверить качество боксов.
3. Реализовать геометрию таблицы, отладить на странице-примере.
4. Добавить валидацию и dedup.
5. Прогнать весь каталог → сверить с `образец.xlsx` (эталон структуры: шапка,
   числа как numeric, разворачивание сплавов в отдельные строки, отсев
   служебных строк вроде `ЕСЛИ ЕСТЬ НЕСКОЛЬКО СПЛАВОВ`).
6. Итог: `result.xlsx` и отчёт о точности.
